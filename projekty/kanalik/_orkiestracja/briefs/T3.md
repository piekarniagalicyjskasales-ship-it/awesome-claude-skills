# T3 — Testy API i WebSocket

Przeczytaj `/home/user/kanalik/_orkiestracja/plan.md` — sekcja KONTRAKT to specyfikacja, którą testujesz. Backend powstaje równolegle, więc testy pisz WYŁĄCZNIE pod kontrakt (nie zaglądaj do implementacji, nie dopasowuj się do niej).

## Plik
`tests/api.test.js` — `node:test` + `node:assert/strict`, globalny `fetch`, pakiet `ws` (zainstalowany).

## Setup
- `before`: `const { start } = require('../src/app')`; `start({ port: 0, dbPath: <tmp>/test.db, uploadsDir: <tmp>/uploads, seed: false })` gdzie `<tmp>` = `fs.mkdtempSync(path.join(os.tmpdir(), 'kanalik-'))`. `after`: `close()` + usunięcie katalogu.
- Helpery: `api(method, path, body, token)` → `{status, body}`; `register(name)`; `connectWs(token)` zwracający obiekt z `waitFor(predicate, timeoutMs=2000)` (bufor odebranych wiadomości, żeby nie zgubić eventów przyszłych przed wywołaniem waitFor) i `close()`.

## Pokrycie (min. jeden test na punkt)
1. Rejestracja: 201 + token + user; duplikat 409; zły username 400; krótkie hasło 400.
2. Login poprawny 200, zły 401; `/api/me` bez tokenu 401; logout unieważnia token.
3. Tworzenie kanału 201; zła nazwa 400; duplikat 409; drugi user widzi go w `/browse` z `isMember:false`, dołącza, widzi w `/api/channels`.
4. Kanał prywatny: niewidoczny w browse dla obcego, join → 403, GET messages obcego → 403; po `POST /members` członek ma dostęp.
5. Wiadomości: wysłanie, pobranie (kolejność rosnąca), paginacja `before`/`limit`, pusty tekst 400, nie-członek 403.
6. Edycja (autor ok + editedAt; inny 403), usuwanie (soft: deleted true, text ""), reakcje toggle (count 1 → 0).
7. Wątki: odpowiedź z parentId; nie pojawia się w liście kanału; `/thread` zwraca replies; replyCount rodzica = 1; parentId odpowiedzi jako rodzic → 400.
8. DM: `POST /api/dms` dwa razy zwraca ten sam id; `isDm:true`, `dmUser` = drugi; osoba trzecia → 403 na messages.
9. Unread: B wysyła 2 wiadomości → u A `unreadCount` 2; po `/read` z id ostatniej → 0; własne wiadomości nie liczą się.
10. Search: znajduje frazę (bez względu na wielkość liter) tylko w kanałach członkowskich; `q` 1 znak → 400; `%` nie działa jak wildcard.
11. Pliki: upload małego PNG (base64) 201 → GET `file.url` zwraca te same bajty i `content-type: image/png`; >5 MB → 413; wiadomość z fileId ma `file`.
12. WebSocket: zły token → zamknięcie 4001; `hello`; B dostaje `message.created` dla kanału, w którym jest; NIE dostaje eventów z prywatnego kanału, w którym nie jest; `typing` trafia do drugiego członka; `presence` online:true przy połączeniu i online:false po zamknięciu.
13. XSS-niezależność API: tekst `<script>` zapisywany i zwracany dosłownie (escape to zadanie frontendu).

## Sprawdź sam
`node --check tests/api.test.js`. Jeśli `src/app.js` już istnieje, możesz uruchomić `npm test` — ale NIE poprawiaj backendu; rozbieżności wypisz w raporcie jako wątpliwości (z odniesieniem do punktu kontraktu).
