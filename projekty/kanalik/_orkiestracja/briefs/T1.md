## Do zrobienia
- `server.js`, `src/app.js` (eksport `start`), dowolne dalsze moduły w `src/` (np. `db.js`, `auth.js`, `routes.js`, `realtime.js`, `seed.js`).
- Baza: `node:sqlite` (`const { DatabaseSync } = require('node:sqlite')`). Włącz `PRAGMA foreign_keys=ON`, `journal_mode=WAL`. Schemat: users, sessions, channels (is_dm, is_private, is_default), channel_members (last_read_message_id), messages (parent_id, file_id, deleted, edited_at), reactions (PK message_id+user_id+emoji), files.
- Wycisz ostrzeżenie ExperimentalWarning dla SQLite (np. `process.removeAllListeners('warning')` + własny listener, który ignoruje tylko SQLite) — opcjonalne.
- Express: `express.json({limit:'8mb'})`, statyczne `public/` (index.html dla `/`), `/files/:id` (walidacja id regex `^[a-f0-9]{32}$`).
- WebSocket `ws` na tym samym serwerze HTTP, ścieżka `/ws`. Mapa userId -> Set<socket>. Presence: broadcast przy pierwszym połączeniu i po zamknięciu ostatniego.
- Pole `online` w User liczone z mapy połączeń.
- Hasła: `crypto.scryptSync(password, salt, 64)`, porównanie `crypto.timingSafeEqual`.
- avatarColor: deterministyczny z palety ośmiu kolorów (np. po id).
- Wszystkie zapytania parametryzowane (żadnej konkatenacji SQL z danymi użytkownika). LIKE w search: escapuj `%` i `_`.
- `close()` zamyka WS, serwer HTTP i bazę.
- `README.md` po polsku: opis, funkcje, wymagania (Node >= 22.5), uruchomienie (`npm install`, `npm start`), konta demo, zmienne środowiskowe (PORT, DB_PATH, UPLOADS_DIR), `npm test`, struktura projektu, krótki opis API/WS (odsyłacz do kontraktu nie wystarczy — krótka tabela).
