## Backend (wykonawca T1) — pliki: server.js, src/*, README.md
- **W1**: `POST /api/channels` i każda inna ścieżka tworząca zwykły kanał odrzuca nazwy zaczynające się od `dm-` → 400 `{error:"Nazwa zarezerwowana"}`. `POST /api/dms` nigdy nie zwraca 500.
- **W2**: asynchroniczny `crypto.scrypt` (promisify) w register/login; błędy przez `next(err)`. Hasło max 200 znaków (400). Limiter w pamięci tylko dla NIEUDANYCH logowań: klucz `ip + ':' + username`, 10 nieudanych prób w 10 min → 429 `{error:"Zbyt wiele prób logowania. Spróbuj za kilka minut."}` (także dla 11. próby z poprawnym hasłem); udane logowanie czyści licznik. Mapa sprzątana (np. przy każdym wpisie usuwaj przeterminowane albo setInterval czyszczony w `close()`). Rejestracji NIE limituj.
- **W3**: `WebSocketServer({ noServer: true, maxPayload: 16 * 1024 })`. Kontrakt zostaje: zły token → połączenie zamykane kodem 4001 (test tego wymaga). Dodatkowo nie nasłuchuj `message` na socketach z niepoprawnym tokenem.
- **W4**: każdy socket zna swój token; `POST /api/auth/logout` zamyka wszystkie sockety z tym tokenem kodem 4001 (i aktualizuje presence).
- **W5**: heartbeat serwera: co 30 s `ws.ping()`, socket bez `pong` od poprzedniego cyklu → `terminate()`. Interval czyszczony w `close()`.
- **D1**: `fileId` musi należeć do wysyłającego (inaczej 403).
- **D3**: wyszukiwanie bez rozróżniania wielkości liter także dla polskich znaków (np. zarejestrowana funkcja SQLite `db.function('lower_u', s => String(s ?? '').toLowerCase())` i porównanie `lower_u(text) LIKE lower_u(?) ESCAPE '\'`), escape `%`/`_` zostaje.
- **D4**: dla odpowiedzi aplikacji (statyczne + API): `Content-Security-Policy: default-src 'self'; img-src 'self' data: blob:; connect-src 'self' ws: wss:; style-src 'self' 'unsafe-inline'; script-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`. (Nagłówki `/files/:id` zostają jak są.)
- **D6**: limit parsera JSON 8 MB tylko dla `POST /api/files`; wszędzie indziej 100 kB.
- **D7**: odpowiedź w wątku do usuniętej wiadomości → 400.
- **D8**: `leave` emituje `channel.updated` (z nowym memberCount, perspektywa odbiorcy) do pozostałych członków.
- **D9**: `PATCH /api/channels/:id` na DM → 400.
- **D10**: event `typing`: walidacja członkostwa (jeśli brak) i ograniczenie 1 event / s na (user, channel, parentId) — nadmiarowe ignorowane.
- **D17**: register normalizuje username do lowercase przed walidacją (`Zenek` → `zenek`, 201).
- **D18**: `/read` przycina `messageId` do MAX(id) w danym kanale.
- **D19**: `/files/:id` przez `res.sendFile` (z zachowaniem nagłówków), zapis uploadu `fs.promises.writeFile`.
- **README**: sekcja „Bezpieczeństwo i znane ograniczenia”: limit logowań, CSP, heartbeat; ograniczenia: brak kwoty plików i sprzątania sierot (D2), sesje bez wygasania i tokeny jawne w bazie (D5), token w URL WebSocket (D11) — z sugestią rozwiązania produkcyjnego.

## Frontend (wykonawca T2) — pliki: public/*
- **D12**: `formatText` — poprawne przywracanie zagnieżdżonych placeholderów (albo placeholdery, które nie mogą się zagnieździć); zero wycieku znaczników do DOM, nadal pełny escape.
- **D13**: `presence`/`user.updated` nie mogą kasować trwającej edycji tematu ani tekstu w kompozytorze — aktualizuj tylko elementy kropki/nazwy albo pomijaj `renderHeader()` podczas edycji.
- **D14**: reset throttle typing (`lastTyping = 0`) po wysłaniu wiadomości.
- **D15**: po wczytaniu strony wiadomości, jeśli lista nie ma paska przewijania, a są starsze → automatycznie dociągnij kolejną stronę (do skutku lub braku starszych).
- **D16**: `message.created` dopisuje element na końcu (bez przerysowania całości, z poprawnym grupowaniem i separatorem dnia), `message.updated` podmienia tylko dany element. Pełny render tylko przy zmianie kanału / loadOlder / reconnect.
- **CSP**: aplikacja musi działać przy `script-src 'self'` — zero inline `<script>`, zero atrybutów `on*=` w HTML i w generowanych stringach, bez `eval`/`new Function`. Inline `style` dozwolone.
