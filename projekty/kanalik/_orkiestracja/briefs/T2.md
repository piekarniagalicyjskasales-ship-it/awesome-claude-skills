# T2 — Frontend Kanalik

Przeczytaj `/home/user/kanalik/_orkiestracja/plan.md` — sekcja KONTRAKT definiuje API i WebSocket, których używasz. Backend powstaje równolegle; pisz ściśle pod kontrakt.

## Pliki
`public/index.html`, `public/styles.css`, `public/app.js` — czysty JS (bez frameworków, bez CDN, bez bundlera), `<script src="/app.js" defer>`.

## Wymagane widoki i funkcje (UI po polsku)
1. **Ekran logowania/rejestracji** — przełączane zakładki; token w `localStorage` (`kanalik.token`, w try/catch); po zalogowaniu widok główny. Wylogowanie.
2. **Układ główny (3 kolumny)**:
   - Lewy sidebar: nazwa workspace "Kanalik" + mój profil (avatar z inicjałami w kolorze avatarColor, kropka online, status); wyszukiwarka; sekcja "Kanały" (`#nazwa`, 🔒 dla prywatnych, pogrubienie + licznik przy unreadCount>0, przycisk „+” → modal tworzenia, link „Przeglądaj kanały”); sekcja "Wiadomości bezpośrednie" (DM z kropką obecności, przycisk „+” → wybór użytkownika).
   - Środek: nagłówek (nazwa kanału lub rozmówcy DM, temat — edycja kliknięciem, liczba członków, przycisk „Dodaj osobę” dla kanałów nie-DM, „Opuść kanał”); lista wiadomości; kompozytor.
   - Prawy panel (otwierany): wątek (rodzic + odpowiedzi + własny kompozytor) LUB wyniki wyszukiwania (klik przenosi do kanału).
3. **Lista wiadomości**: grupowanie kolejnych wiadomości tego samego autora w ciągu 5 min (bez powtarzania avatara/nazwy); separatory dni („Dzisiaj”, „Wczoraj”, data po polsku); godzina HH:MM; „(edytowano)”; usunięte jako „Ta wiadomość została usunięta.” kursywą; reakcje jako pigułki (emoji + liczba, podświetlone gdy moja; klik = toggle); pod wiadomością „N odpowiedzi” → otwiera wątek; obrazek-załącznik jako miniatura (max 360px), inny plik jako link do pobrania.
   - Akcje na hover: dodaj reakcję (mały picker 8 emoji: 👍 ❤️ 😂 🎉 😮 😢 🙏 ✅), odpowiedz w wątku, edytuj i usuń (tylko moje; usunięcie z `confirm`). Edycja inline (Enter zapisuje, Esc anuluje).
   - Doładowanie starszych przy przewinięciu do góry (`before`), zachowanie pozycji przewijania. Autoscroll w dół gdy użytkownik był przy dole.
4. **Formatowanie tekstu** (NAJPIERW escape HTML całego tekstu, potem transformacje): ```` ```blok``` ````, `` `kod` ``, `*pogrubienie*`, `_kursywa_`, `~przekreślenie~`, linki http(s) jako `<a target="_blank" rel="noopener noreferrer">`, `@username` podświetlone (mocniej gdy to ja), nowe linie jako `<br>`. Nigdy nie wstawiaj niezescapowanych danych do innerHTML (dotyczy też nazw kanałów, displayName, tematów, nazw plików).
5. **Kompozytor**: textarea auto-rosnąca; Enter = wyślij, Shift+Enter = nowa linia; przycisk załącznika (input file → base64 → POST /api/files → wysłanie z fileId; podgląd nazwy przed wysłaniem; limit 5 MB komunikat); placeholder „Napisz do #kanał”; wysyłanie zdarzenia `typing` max raz na 3 s; nad kompozytorem „X pisze…” (znika po 4 s bez nowych eventów).
6. **Realtime** (WebSocket `/ws?token=`, protokół ws/wss wg location): obsłuż wszystkie eventy z kontraktu; ping co 25 s; automatyczny reconnect z backoffem (1,2,4..max 15 s) i po reconnect odświeżenie kanałów i bieżących wiadomości. Nowa wiadomość w innym kanale → unreadCount++ lokalnie (gdy autor ≠ ja). W otwartym kanale → POST /read z id ostatniej wiadomości (gdy karta widoczna). Tytuł karty: `(N) Kanalik` gdy są nieprzeczytane.
7. **Modale**: utwórz kanał (nazwa — automatycznie lowercase i spacje→`-`, temat, checkbox prywatny); przeglądaj kanały (lista z „Dołącz”/„Otwórz”); nowy DM (lista użytkowników z filtrem); dodaj osobę do kanału; edycja profilu (displayName, status). Zamykanie Esc i klikiem w tło.
8. **Routing**: `location.hash = #/c/<channelId>`; po starcie otwórz kanał z hasha lub `ogolny`/pierwszy.
9. **Błędy**: toast na dole z komunikatem `error` z API; 401 → wyloguj do ekranu logowania.

## Design (własny, NIE Slack)
- Paleta: sidebar ciemny granat-zieleń `#0e2a2f`, tekst sidebara `#cfe3e2`, akcent bursztynowy `#f2a541`, aktywny kanał tło `#1f4e55`; treść jasna `#ffffff`/`#f6f7f8`, tekst `#1d2329`, linie `#e3e6e8`. Zdefiniuj jako zmienne CSS na `:root`; dodaj tryb ciemny przez `@media (prefers-color-scheme: dark)` dla obszaru treści.
- Font systemowy (`system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`), 15px. Zaokrąglenia 6–8 px, delikatne cienie modali.
- Responsywność: < 760px sidebar chowany za przyciskiem ☰, prawy panel na pełną szerokość.
- Dostępność: przyciski jako `<button>` z `aria-label`/`title`, focus widoczny, kontrast AA.
